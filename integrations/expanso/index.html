Expanso with Makoto

Edge-to-cloud pipelines can attest local source batches before data leaves the site.

Design note: This is an implementation pattern, not a shipped adapter. The attachment points use real Expanso APIs; the Makoto calls show where signed evidence would enter the lifecycle.

What is Expanso?

Expanso processes data close to its source using declarative pipelines. The useful Makoto boundary is a durable local batch or output object: the pipeline can preserve acquisition context, write exact bytes, invoke an operator-controlled signer, and send the artifact with its signed evidence.

Where Makoto attaches

Primary pattern: Bloblang mapping + Command processor + Custom processor plugin. Below are the integration options ordered by lift required.

How Makoto attaches to Expanso

  • Mapping context — Preserve source URI, collection window, node, connector, and transformation parameters as inputs to operation metadata.
  • Durable batch boundary — Write the exact local batch first; do not sign a transient message object that downstream systems cannot reproduce.
  • Command or plugin boundary — Invoke the checked-out Makoto CLI or a future tested processor with protected keys after the output commits.
  • Edge-to-cloud handoff — Transfer artifact, statement graph, and signed handoff; the cloud recipient verifies with its own policy and expected bytes.

Implementation sketch

Attest a durable edge batch

The pipeline writes canonical NDJSON and source metadata, then invokes the real origin command.

# DPL first writes /artifacts/temperature-window.ndjson and source.json.
uv run makoto attest origin \
  --subject "temperature-window.ndjson=/artifacts/temperature-window.ndjson" \
  --source-kind "urn:example:source:mqtt-window" \
  --source-uri "mqtt://factory-7/sensors/temperature" \
  --source-metadata /evidence/source.json \
  --profile /policy/temperature-window.profile.json \
  --schema-catalog /policy/catalog.json \
  --key /run/keys/site-origin.private.pem \
  --out /evidence/temperature-origin.dsse.json

# The cloud receiver verifies the eventual bundle independently.
uv run makoto verify bundle --help
