Apache Spark with Makoto

Attest stable dataset writes and micro-batch windows, not ephemeral scheduler stages.

Design note: This is an implementation pattern, not a shipped adapter. The attachment points use real Apache Spark APIs; the Makoto calls show where signed evidence would enter the lifecycle.

What is Apache Spark?

Apache Spark executes a logical job as many retryable physical stages. Stage events are useful runtime metadata, but stable evidence belongs at committed dataset, table-snapshot, or micro-batch boundaries where exact input and output identities can be recovered.

SparkListener APISubscribe to stage start/end events for free attestations
UDF for Hashing`makoto_hash()` UDF computes content digests in parallel
Catalog IntegrationUnity Catalog + Iceberg tables surface lineage already
Structured StreamingPer-batch attestations on streaming queries

Where Makoto attaches

Primary pattern: SparkListener + UDF + DataFrame writer wrapper. Below are the integration options ordered by lift required.

How Makoto attaches to Apache Spark

  • Writer completion — After a DataFrame write commits, hash or manifest the exact output files and bind them to signed predecessor subjects.
  • Table commit hook — Iceberg or Delta snapshot identifiers can locate immutable material; the statement still binds the files or signed manifest that represents that snapshot.
  • Streaming foreachBatch — Treat a declared offset/time window as one bounded artifact or dataset manifest, then append one transformation statement for that window.
  • Listener metadata — Capture application, job, stage, retry, and code context as operation metadata without pretending a stage event is the data.

Implementation sketch

Write first, attest the committed artifact

The Spark job owns data production; a post-write task invokes the checked-out reference CLI.

// Application code writes a deterministic partition set or table snapshot.
cleaned.write.mode("overwrite").parquet("/artifacts/curated-orders")

# After commit, build a signed dataset manifest when output spans files.
# The manifest and input binding must resolve exact bytes and predecessor evidence.
uv run makoto attest transform \
  --subject-binding /evidence/output-subject.json \
  --input-binding /evidence/input-binding.json \
  --operation-type "urn:example:spark:dataset-write" \
  --operation-metadata /evidence/spark-application.json \
  --key /run/keys/transform.private.pem \
  --out /evidence/curated-orders.dsse.json

Where this pattern would matter

Lakehouse Provenance

Iceberg or Delta tables ship with attestations matched to snapshot IDs.

ML Feature Pipelines

Every feature view emits a Makoto evidence consumed by your model registry.

Cross-region Replication

Prove the destination dataset is byte-identical to the source after replication.

Hard-Multi-Tenant Clusters

Per-job Makoto evidence prove tenant A's job didn't pollute tenant B's data.
