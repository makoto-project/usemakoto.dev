The provenance casebook

Data provenance fails in familiar, expensive ways.

These are cases in which data left its source and someone later needed to prove what happened. Each case names the evidence Makoto needs to carry and the decision a receiver can make with it.

Featured case · one dataset, attested three times

What happens to the evidence when the data changes?

A dataset is attested, then normalized, then reduced to a public-safe derivative. Each edit produces different bytes, so each edit needs its own statement — and each new statement carries the identity of the one before it at the foot of the document, which is what turns three assertions into a chain.

The walkthrough shows every document in full, the digests that changed at each step, and what a receiver can and cannot conclude from them.

Follow one dataset through attest, change, and re-attest →

  1. 01
    AttestBind an origin statement to the exact source bytes.
  2. 02
    ChangeNew bytes, new digest, and a gap no statement covers.
  3. 03
    Re-attestA transformation statement naming its predecessor.
  4. 04
    TransformDrop identifiers, generalise, and re-attest again.
Featured case · independent handoff

Can the receiver verify the story without trusting the producer’s system?

A producer creates source data, signs its origin, normalizes it, produces a public-safe derivative, and signs the handoff. The receiver starts with its own schemas and signer policy, reconstructs the graph, and hashes the bytes it actually received.

Run the full producer-to-receiver proof →

  1. 01
    SourceBind collection claims to exact source bytes.
  2. 02
    TransformPoint each step to its exact predecessor.
  3. 03
    HandoffSign roots, profiles, and the final artifact.
  4. 04
    VerifyApply receiver-owned policy and re-hash the data.

Six ways the history gets lost

  1. 01

    Poisoned pipeline

    A corrupted sensor file carries impossible readings, duplicate rows, and a malicious payload into downstream tables. Predecessor links expose the blast radius and the signed claims that admitted it.

    Open case →
  2. 02

    Scientific reproducibility

    A paper cites experiment.csv, but the outlier removal, normalization, and original source have disappeared with the people who ran them. The lineage graph preserves a path back to the result.

    Open case →
  3. 03

    Dataset release

    A release includes the data but not the evidence. Attach signed origin, transformation, and digest records so consumers can inspect exactly what shipped.

    Open case →
  4. 04

    Configuration postmortem

    Throughput falls after a weekend change made by a service account. A transformation claim records the configuration, code identity, executor, and affected artifact at the time of the run.

    Open case →
  5. 05

    AI dataset gate

    A plausible label has been poisoned. The model builder refuses data unless its source, processing steps, authorized attesters, required profiles, and final bytes verify.

    Open case →
  6. 06

    Invisible Unicode

    Signatures and hashes prove the hidden characters were not altered; they do not make the characters safe. A profile requires an explicit analysis and a normalization or rejection decision.

    Open case →

The evidence patterns inside those cases

PatternWhat it recordsWhy it matters
Origin statementSource identity, collection method, acquisition time, governing claims, and the source artifact digest.Every lineage graph has a defensible beginning.
Transformation statementInput statement and artifact digests, output digest, transformation identity, code reference, parameters, and executor claims.Each step can be checked without editing the step before it.
Stream windowA bounded time or offset range, partition identity, record count, and a digest or Merkle root for that window.Streaming systems can attest to stable windows instead of pretending the stream is one static file.
Bundle and handoffThe statement graph, required profiles, roots, final artifact, and completeness claims selected for transfer.The receiver knows what evidence was intentionally delivered and what it must resolve.
Signed envelopeThe exact statement payload plus one or more DSSE signatures.Content tampering becomes detectable, while authorization remains a receiver policy decision.

The documents themselves

Each pattern above is a real file. These are complete, unabridged, and valid against the published schemas; every digest in them was computed from bytes checked into this repository.

subject[].digest.sha256
The artifact this statement is about, identified by content rather than by name. Rename the file and the statement still applies; change one byte and it no longer does.
predicate.source.kind
What class of thing the data came from. A receiver policy matches on this, so it is a controlled value rather than free prose.
predicate.source.uri
The specific endpoint or location. Informative; a receiver cannot verify it from the statement.
predicate.source.retrievedAt
When the bytes were pulled, as distinct from when the statement was written.
predicate.event.id
A stable identifier for the collection run, so two statements about the same bytes can be told apart.
predicate.extensions
Open by design. Collector identity, origin geography, and lawful basis live here rather than as first-class fields. A receiver may read them; core verification does not check them.

predicate.operation.type
What kind of step this was. Receiver policies authorize signers per operation type, so a key trusted to normalize is not automatically trusted to anonymize.
predicate.operation.tool
Name, version, and repository of the code that ran, for reproducibility.
predicate.operation.parametersDigest
A hash of the configuration, not the configuration itself. The parameters can be published, withheld, or held internally without changing what this statement commits to.
predicate.inputs[].digest
The bytes this step consumed. A receiver compares this against the predecessor's subject digest; a mismatch means something was substituted between steps.
predicate.inputs[].provenance.statementDigest
The predecessor statement's identity, and therefore the edge in the graph. Because it is the hash of the whole previous statement, the edge cannot be rewired without re-signing everything downstream.
predicate.inputs[].provenance.subjectName
Which subject of that predecessor is meant, for statements carrying more than one.

Stream window

predicate https://usemakoto.dev/predicate/v0.2/origin

Streaming systems cannot attest to a stream, because a stream has no final bytes. They attest to bounded windows of it. Here one tumbling minute of sensor readings is serialized to newline-delimited JSON and treated as an artifact like any other.

Read this before reading the document. Makoto defines exactly two predicate types, origin and transformation. There is no normative stream-window predicate. The window boundaries, the partition list, and the Merkle root below are producer claims carried in extensions. A receiver cannot verify any of them from this statement.

What a receiver does verify is the subject digest: c4c2f3be19a1f816d5fe22a69b47a221ee84a29e6b3066d2b71241b8ddd14c64, the SHA-256 of the serialized window file. The Merkle root is reproducible from that same file, because the document records the exact leaf, internal-node, and odd-node rules used to build it — but reproducing a value is not the same as a signature covering it.

Bundle index and dataset manifest

schemas bundle.schema.json · dataset-manifest.schema.json

The earlier format collected a dataset's whole history into one aggregate document, a data bill of materials. The current specification splits that job. The bundle index maps statement digests to transport paths and claims no authority of its own; a separately signed handoff is what commits to the graph.

Dataset study · SQuAD

Unknown is better than invented.

The retained SQuAD record is useful because it shows what a provenance tool must not do. The public dataset has a familiar source and a final artifact, but intermediate hashes were not published and no third party attested to bias, quality, or regulatory claims.

Those absences belong in the record. Makoto can distinguish signed evidence from reconstructed narrative; it cannot retroactively create proof that the source pipeline never emitted.

SQuAD is a good subject precisely because its provenance is unusually well documented for a public dataset. The source corpus is an English Wikipedia snapshot, the annotation was crowdsourced through Mechanical Turk, and the processing is described in the paper. Three distinct transformations, each with inputs and outputs that could have been hashed.

They were not. The record says so, in the places where a digest should be:

{
  "step": 1,
  "description": "English Wikipedia articles (October 2015 snapshot) were filtered to 536 articles covering a range of topics, then converted from raw MediaWiki markup to plain text.",
  "tool": "Wikipedia Extractor",
  "tool_version": null,
  "repository": null,
  "inputs": [
    {
      "name": "English Wikipedia dump",
      "uri": "https://dumps.wikimedia.org/enwiki/",
      "snapshot": "2015-10",
      "digest": "sha256:NOT_PUBLISHED",
      "provenance_gap": true,
      "note": "The exact dump date and file used are not documented in the SQuAD paper or dataset card."
    }
  ],
  "operations": [
    "Selected 536 Wikipedia articles across diverse topics",
    "Converted MediaWiki markup to plain text, stripping citations, tables, and infoboxes",
    "Segmented articles into paragraphs for use as reading passages"
  ],
  "output_digest": "sha256:NOT_PUBLISHED",
  "note": "Intermediate passage corpus was never published as a standalone artifact."
}

Two fields carry the whole point. digest reads sha256:NOT_PUBLISHED rather than a plausible-looking hex string, and provenance_gap is true. A generator that invented a digest here would produce a record that looks stronger and is worth less, because a consumer could no longer tell a verified step from a reconstructed one.

The same discipline applies at the top level and at the end:

{
  "signature": {
    "algorithm": "sha256",
    "digest": "sha256:COMPUTE_FROM_plain_text_train_validation_parquet_files",
    "signed_at": "2026-03-07T00:00:00Z",
    "signed_by": "https://github.com/rajpurkar.keys",
    "provenance_gap": true,
    "note": "No canonical artifact hash has been published by the dataset authors. The HuggingFace-hosted Parquet files would need to be hashed at a specific commit to produce a stable digest."
  },
  "attestations": [],
  "attestation_gaps": [
    {
      "type": "bias_audit",
      "note": "No third-party bias audit has been conducted or signed against a specific dataset version. Known bias: Wikipedia over-represents certain topics, demographics, and writing styles."
    },
    {
      "type": "regulatory_compliance",
      "note": "No attestation for EU AI Act, CRA, or equivalent regulatory compliance exists for this dataset."
    },
    {
      "type": "quality_certification",
      "note": "No independent quality certification exists. The paper reports human-level F1 of 86.8 on validation, but this is a model benchmark, not a dataset quality attestation."
    }
  ]
}

The dataset authors never published a canonical artifact hash, so the signature block records a gap instead of a number. The attestations array is empty: no third party has certified this dataset for bias, quality, or regulatory compliance. attestation_gaps then names the three specific certifications that are missing and why each one would matter — an absence stated precisely is actionable, where an absence left implicit is invisible.

In a world where those fields are populated — where an audit firm signs a bias finding against a specific digest, or a regulator attests to EU AI Act compliance — that signature travels with the data permanently, and a consumer can check it without contacting either party.

This record is in the earlier aggregate DBOM shape, not the current statement shape, and is kept as a dataset study rather than as a format example. The current equivalents are the documents above.

Inspect the SQuAD record · Use the dataset analysis prompt

Try it on a dataset you care about

The fastest way to find out what your own data cannot prove is to attempt the record and see where it goes blank.

Generate a draft record for a public dataset

Point any capable model at a dataset card and its paper using the dataset analysis prompt. It produces a draft record and, more usefully, a list of the provenance gaps it could not fill. Those gaps are the signal; the filled fields are the easy part.

curl -sO https://usemakoto.dev/prompts/dbom-generation-prompt.md
# then paste it, plus a dataset card URL, into the model of your choice

Compare what comes back against the SQuAD record. If your draft has fewer gaps than SQuAD's, be suspicious of it rather than pleased with it.

Reproduce the digests on this page

Artifact digests are plain file hashes. Statement digests are taken over the canonical serialization of the statement, so hash that rather than the pretty-printed file:

curl -sO https://usemakoto.dev/attestations/origin-example.json
shasum -a 256 origin-example.json   # the file as served, not the statement digest
import hashlib, json, urllib.request

BASE = "https://usemakoto.dev/attestations/"
for name in ("origin-example", "transform-example", "public-transform-example"):
    raw = urllib.request.urlopen(BASE + name + ".json").read()
    canonical = json.dumps(json.loads(raw), sort_keys=True, separators=(",", ":"))
    print(hashlib.sha256(canonical.encode()).hexdigest(), name)

Each printed digest should match the one the next statement in the chain names as its predecessor. The walkthrough shows that chain end to end.

Run the whole thing locally

The reference implementation builds the graph, signs it, hands it off, and verifies it as an independent receiver, then runs seven tampering cases that each produce a named denial. No credentials, no service, no Docker.

git clone https://github.com/makoto-project/makoto.git
cd makoto
uv sync --locked --dev
./scripts/demo-v0.2.sh --acceptance
