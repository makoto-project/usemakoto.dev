Language interfaces

The protocol is portable. The supported implementation is explicit.

Makoto currently ships as source: a Python reference library and command-line interface in the core repository. JavaScript, browser, Go, and other language work should reproduce the same signed bytes and verification decisions, not invent a friendlier but incompatible document.

InterfaceCurrent stateUse today
Command-line interfaceImplemented and tested in the core repositoryCreate keys, attest origins and transformations, build handoffs, validate schemas, and verify bundles.
Python libraryReference implementation in the source treeEmbed the same schema, signing, graph, profile, and verification logic behind a controlled integration.
JavaScript and browserInterface research; no published packageReview the client-side requirements and help define byte-for-byte interoperability tests.
Go and other languagesNo maintained SDK claimedStart from schemas, test vectors, canonicalization rules, and stable verification diagnostics.
Reference path

Command line

The CLI is the shortest route to every protocol operation without binding a pipeline to Python internals.

git clone https://github.com/makoto-project/makoto.git
cd makoto
uv sync --locked --dev
uv run makoto --help
uv run makoto attest origin --help
uv run makoto attest transform --help
uv run makoto handoff create --help
uv run makoto verify bundle --help

Maintained source

Python

The Python package is the reference implementation used by the CLI and tests. It is not advertised as a separately published distribution, and its internal modules are not yet a stable public SDK. Use the command line for the supported boundary; read these modules when reviewing or contributing to the implementation.

Implemented moduleResponsibility
makoto.modelConstruct statement, predicate, subject, and handoff model objects.
makoto.dsseSign and verify exact DSSE payload bytes.
makoto.schema and makoto.schema_catalogStrict JSON parsing, core validation, and digest-pinned resource resolution.
makoto.graph, makoto.policy, and makoto.reportEvaluate graph structure, receiver authorization policy, and machine-readable outcomes.
makoto.bundleSafely read and verify a complete portable handoff bundle.

Interop contract

What every future SDK must preserve

  1. Exact bytesDo not parse and silently rewrite signed JSON. DSSE authenticates the payload bytes that were actually signed.
  2. Closed core shapesCore statements stay portable and strict. Team-specific fields enter through declared, digest-pinned profiles.
  3. Independent policySignature validity and signer authorization are separate results. The receiver supplies trust policy outside the bundle.
  4. Graph identityTransformation inputs bind both the predecessor statement digest and the exact subject digest.
  5. Stable failuresImplementations should agree on allow/deny behavior and machine-readable diagnostic codes for the conformance fixtures.
JavaScript and browser design

The browser is a useful verifier surface, but not a shortcut around trust.

A future browser library can hash received ArrayBuffer bytes, validate schemas from a pinned catalog, verify Ed25519 signatures, and render a report. It still needs receiver-owned authorization policy, explicit expected heads or manifests, resource limits, and negative test vectors. No CDN import or package name is promised until those constraints are implemented and tested.

Bring the runtime you need, implement one positive fixture and every relevant denial, then propose the API around behavior we can compare.
