Language interfaces

The protocol is portable. The supported implementation is explicit.

Makoto ships as source: a Python reference library and command-line interface in the core repository, pinned on this site to revision 0e41afbd0c3f. Every language binding and platform integration here drives that one implementation, so a Bash step, a Go sidecar, and an Airflow DAG reach the same decision on the same bundle. There is no published package on PyPI, npm, or the Go module proxy.

InterfaceCurrent stateUse today
Command-line interfaceImplemented and tested in the core repositoryEvery protocol operation: keys, origin and transformation statements, handoffs, schema validation, and bundle verification.
Python libraryReference implementation in the source tree; internal modules are not a stable APIIn-process verification from inside a pinned checkout, when a subprocess per bundle is too costly.
Bash, Python, JavaScript, TypeScript, and Go bindingsDocumented, executed recipes over the CLI and its JSON reportGate a job, service, or CI step on a verdict today, with install, attestation, verification, denial handling, and report reading.
JavaScript and browserInterface research; no published packageServer-side verification through the JavaScript binding. A native browser verifier is open work.
Go and other native verifiersNo maintained SDK claimedStart from the schemas, conformance fixtures, canonicalization rules, and published diagnostic codes.
Pipeline platformsRunnable patterns, not shipped adaptersNine platforms wired through one shared helper, each page stating exactly how it was tested.

How verification decides →

Each binding is one complete program that was run against the pinned core before publication, with its real output shown. All five follow the same six steps: install, validate structure against the hosted schemas, sign an origin statement, verify a handoff bundle, refuse a tampered copy, and read the report.

The contract every binding relies on

A binding is thin because the contract is small. Automate on the exit status and the JSON report, never on human-readable output.

0 · allow
Every required check passed under the exact policy and expectations supplied. stdout holds the report.
1 · deny or indeterminate
stdout holds a complete report; primaryError names the boundary that failed.
2 · invalid input
No report. stderr carries one JSON object with errorClass and message.
3 · internal error
No report. Treat it as an outage, never as a verdict.

The report’s shape is published as the verification-report schema, and every diagnostic code is listed by step in the ordered checks.

Reference path

Command line

The CLI is the shortest route to every protocol operation without binding a pipeline to Python internals. Install it from a reviewed revision:

git clone https://github.com/makoto-project/makoto.git
cd makoto
git checkout 0e41afbd0c3f1c389d6643bfe279ab159e4f53ac
uv sync --locked --dev
uv run makoto --help
makoto key generate
Write an Ed25519 key pair: --private-out at mode 0600 and --public-out.
makoto key inspect
Print the key ID a trust policy uses for a public key.
makoto digest
Print the SHA-256 digest of a file in the form statements use.
makoto attest origin
Sign an origin statement: --subject name=path, --source-kind, --source-uri, optional --source-metadata.
makoto attest transform
Sign a transformation: one --input-binding file per input naming its predecessor envelope, plus --operation-type.
makoto envelope inspect / cosign
Show an envelope’s payload digest and signer key IDs, or add a co-signature without changing statement identity.
makoto handoff create
Package heads, reachable statements, and final artifacts into a bundle signed by an authorized handoff key.
makoto verify bundle
Run the fourteen ordered steps against a receiver policy and independent expectations; --json writes the report.
makoto schema validate
Validate a document against a core schema or a digest-pinned profile.
makoto profile create
Create a profile reference that pins a schema by digest and closure digest.
makoto policy check
Validate a trust policy, including the canonical ordering the verifier requires.

Maintained source

Python

The Python package is the reference implementation used by the CLI and its tests. It is not advertised as a separately published distribution, and the PyPI name makoto belongs to an unrelated project. Use the command line for the supported boundary. When a long-running service must verify in-process, the Python binding shows the exact VerificationRequest call the CLI makes, pinned to a revision.

Implemented moduleResponsibility
makoto.modelConstruct statement, predicate, subject, and handoff model objects.
makoto.dsseSign and verify exact DSSE payload bytes.
makoto.schema and makoto.schema_catalogStrict JSON parsing, core validation, and digest-pinned resource resolution.
makoto.graph, makoto.policy, and makoto.reportEvaluate graph structure, receiver authorization policy, and machine-readable outcomes.
makoto.bundleSafely read and verify a complete portable handoff bundle.

JavaScript and browser design

The browser is a useful verifier surface, but not a shortcut around trust.

A future browser library can hash received ArrayBuffer bytes, validate schemas from a pinned catalog, verify Ed25519 signatures, and render a report. It still needs receiver-owned authorization policy, explicit expected heads or manifests, resource limits, and negative test vectors. No CDN import or package name is promised until those constraints are implemented and tested.

This site’s repository keeps an earlier API study in sdk/javascript and sdk/python. It models ergonomics, not the current protocol: its documents are an earlier bill-of-materials format with no signatures over exact payload bytes, no receiver policy, and no handoff, so the verifier on this site cannot check them. Its real interfaces, executed as written, are worth reading for shape:

// sdk/javascript/src: generate(options) and verify(dbom, fileBuffer)
import { readFile } from "node:fs/promises";
import { generate, verify } from "./sdk/javascript/src/index.js"; // needs ajv and ajv-formats

const buffer = await readFile("sales.csv");
const dbom = await generate({ fileBuffer: buffer, fileName: "sales.csv", signer: "github:you" });
const result = await verify(dbom, buffer); // { valid: boolean, errors: string[] }
console.log(result.valid ? "valid" : result.errors); // valid
# sdk/python/makoto: generate(file_path, signer, ...) and verify(...) -> VerifyResult
from pathlib import Path
from makoto import generate, verify  # the study package, not the core implementation

path = str(Path("sales.csv").resolve())
dbom = generate(path, signer="github:you")
print(verify(dbom, file_path=path).valid)  # True
Path(path).write_text(Path(path).read_text() + "3,4\n")
print(verify(dbom, file_path=path).errors)  # ['File hash mismatch: expected 0ae7..., got 4bb0...']

Read, do not deploy. @makoto/sdk was never published to npm, and the Python study is not on PyPI. Its generate also requires an absolute path: a relative one raises ValueError: relative path can't be expressed as a file URI.

Interop contract

What every future SDK must preserve

  1. Exact bytesDo not parse and silently rewrite signed JSON. DSSE authenticates the payload bytes that were actually signed.
  2. Closed core shapesCore statements stay portable and strict. Team-specific fields enter through declared, digest-pinned profiles.
  3. Independent policySignature validity and signer authorization are separate results. The receiver supplies trust policy outside the bundle.
  4. Graph identityTransformation inputs bind both the predecessor statement digest and the exact subject digest.
  5. Canonical orderPolicies, manifests, and catalogs are rejected when arrays are out of canonical order, so two implementations never disagree about identity.
  6. Stable failuresImplementations should agree on allow and deny behaviour and on machine-readable diagnostic codes for every conformance fixture.
Build one language well

An SDK starts with a cross-language conformance result, not an install snippet.

Bring the runtime you need, implement one positive fixture and every relevant denial, then propose the API around behaviour we can compare. The five bindings on this site are the baseline a native implementation must match.
