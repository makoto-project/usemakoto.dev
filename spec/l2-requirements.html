Assurance level

L2: Provenance is authorized and complete.

L2 adds receiver authorization of every signer, a continuous graph from each head to its origins, an authorized handoff whose exact sets match, and received final-artifact bytes that match the signed digests.

Derived, not declared. A level is a named set of verification-report checks (Section 8.3). It is derived only from a completed report that validates against the core verification-report schema, and deriving it never changes a check status, a diagnostic, an exit code, or the allow/deny decision. A level is always relative to the receiver policy, catalog, and expectations that produced the report.

Checks this level requires

Levels are cumulative: every requirement of L1 must also hold. This page lists only what L2 adds.

Each identifier is a top-level check in the verification report. The step is where Section 15 runs it.

CheckVerification stepRequired status
authorization-thresholdsStep 6 — Check authorization thresholdspass
authorizationStep 7 — Finalize statement authorizationpass
graphStep 9 — Build the graphpass
roots-and-headsStep 10 — Discover roots and headspass
completeness-anchorStep 11 — Check the handoff anchorpass
artifact-bytesStep 12 — Verify artifact bytespass
metadata-profilesStep 7 — Resolve metadata profilespass or not_checked
graph-dependency-artifactsStep 8 — Prevalidate dataset-manifest artifactspass or not_checked
artifact-profilesStep 13 — Validate artifact profilespass or not_checked

Also permitted or required

These three checks MAY be not_checked instead of pass. That exception exists because Section 15.1 limits not_checked to optional, waived, or empty populations. Any other status fails the level.

How statuses count

  • Levels are cumulative. A report that does not satisfy L1 has no level, even if later checks passed.
  • not_checked is accepted only where a level explicitly allows it.
  • skipped, fail, and indeterminate never satisfy a level.

What L2 does not establish

L2 does not include an independent freshness anchor, so it is not the level a receiver needs before treating a handoff as current. That is the addition L3 makes.

No level asserts that a signer told the truth, that a transformation executed as described, or that evidence is unforgeable (Section 8.2).

Require this level

The reference CLI reads a report written by makoto verify bundle --json and prints the level reached.

makoto report level report.json --require L2
Exit codeMeaning
0No level was required, or the achieved level meets the requirement.
1The achieved level does not meet the requirement.
2The input is not a schema-valid verification report.

With --json the command writes one deterministic object with exactly decision, level ("L1", "L2", "L3", or null), and levels: an array in L1, L2, L3 order whose entries have exactly decisionRequired, level, satisfied, title, and unmetChecks. Each unmetChecks entry is { "id", "status" }, in canonical check order. When --require is supplied, the object also contains required and meetsRequired.
