Makoto v0.2 specification

A source-first protocol for immutable, signed data provenance; private JSON Schema profiles; consumer-owned authorization; exact-byte artifact binding; and signed handoff completeness.

Status boundary: this page describes the local release candidate. The complete normative text is staged here, but no v0.2 tag or immutable hosted release exists yet.

Design commitments

  1. Start at the source. An origin binds source claims to the exact collected artifact bytes.
  2. Append, never rewrite. Each transformation is a new signed statement referencing exact predecessor statement and input digests.
  3. Separate authenticity from authorization. A valid signature proves key control; only receiver policy grants authority.
  4. Carry completeness explicitly. A signed handoff names the exact statement set, roots, heads, final artifacts, and required profiles.
  5. Extend by digest, not ambient lookup. Public or private profiles resolve offline by URI and exact SHA-256 closure.

Explicit non-goals

v0.2 does not establish source truthfulness, confidentiality, legal compliance, data quality, or that claimed tools actually ran. Formal governance and foundation affiliation are not defined by this protocol candidate.

Compatibility

v0.2 is intentionally not wire-compatible with v0.1. Historical v0.1/L1–L3 material remains available but must not be treated as v0.2 evidence.
