Technical reference

Transformation predicate, version 0.3

One append-only processing event that binds its outputs to exact input artifacts and predecessor statement payloads.

Protocol version 0.3. Published for review beside the current version. It is not yet a tagged release and not the default. The current definition is the transformation predicate.

Predicate type
https://usemakoto.dev/predicate/v0.3/transform
JSON Schema
transform.schema.json
Specification
Section 11.4

Each input carries two bindings

  • Artifact binding: the SHA-256 of the exact input bytes.
  • Provenance binding: the predecessor statement payload digest and subject name that supplied those bytes.
{
  "name": "customers.normalized.json",
  "digest": {"sha256": "…"},
  "provenance": {"statementDigest": {"sha256": "…"}, "subjectName": "customers.normalized.json"}
}

Joins use inputs from multiple predecessors. Splits use multiple output subjects or multiple descendants. Array order never defines lineage.

Dataset members: an optional entryName selects one member of a validated dataset-manifest subject. The verifier needs the exact manifest bytes to prove that membership; without them the edge fails with E_DATASET_MANIFEST_REQUIRED.
