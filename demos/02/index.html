Case 02 · scientific reproducibility

The chart survived. The method did not.

A paper cites an experiment file, but the source instrument export, outlier rule, normalization parameters, and exact plotting input disappeared when the postdoc left.

Evidence boundary. Every terminal block on this page was captured by running the command shown against the checked-in reference fixtures with the Makoto core verifier at commit 0e41afb. The pinned core commit 27d3352 adds verification summaries and a separately dispatched newer protocol version without changing these results, and the gate below runs it. Verification-summary tables are computed from the published reports with its property rules. The verification reports are byte-for-byte the files published under the end-to-end proof. Nothing below was typed by hand.

The problem

A postdoc submits a paper. The methods section cites one data file that supports the central claim. The reviewer asks four questions: which version of the raw data is this, were outliers removed and by what rule, who prepared the file, and can we get back to the original instrument readings?

Nobody can answer. The file passed through three hands over six months, the person who ran the cleaning step has graduated, and the parameters lived in a notebook nobody can find. The result is not a forged dataset. It is a lineage with a hole in it, and a hole looks exactly like a shortcut.

The runnable fixture uses the reference handoff, which has the same shape as a lab pipeline: a source export, two transformations, and a signed handoff. Two poisoned variants of the published evidence are tested: one drops the origin statement, one rewrites a step to claim it consumed the raw export directly.

  1. The raw example

    A complete evidence bundle answers the reviewer's questions from the statements themselves. Decoding each signed statement in the good bundle shows the chain: an origin claim over the raw export, a normalization step that consumed it, and a public-safe step that consumed the normalized file.

  2. How it failed

    Variant one, a missing step. The republished bundle simply leaves out the origin statement. Every remaining signature is still valid and the final bytes are unchanged, so a checksum or signature check passes. The bundle index now lists two statements instead of three.

    Variant two, a rewritten step. The final statement is edited to say it consumed the raw export directly, skipping normalization, and is re-wrapped in a new bundle with the original signature copied across.

  3. Put Makoto in the path

    Figures are rebuilt only from evidence that verifies end to end. A pull request that adds or changes a handoff runs the gate for each bundle the paper cites; the figure rebuild job depends on it.

    The workflow

    # Reproducibility gate for a paper's evidence bundles. A figure
# is rebuilt only from a handoff whose whole lineage verifies.
#
# Copy to .github/workflows/makoto-gate.yml in the repository that
# receives handoffs. Layout it expects:
#   handoffs/<name>/bundle/                  what the sender transferred
#   receiver/policy.json                     receiver-owned trust policy
#   receiver/catalog.json, receiver/resources/  pinned private schemas
#   receiver/expected/<name>.artifact.json   expected final artifact
name: Makoto gate before figure rebuild

on:
  workflow_dispatch:
  pull_request:
    paths:
      - "handoffs/**"

permissions:
  contents: read

env:
  # Pinned so these fixtures replay identically. Delete this line to
  # evaluate against the runner clock.
  EVALUATION_TIME: "2026-09-16T16:00:00Z"

jobs:
  gate:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        include:
          # The sender publishes manifest and head digests out of band.
          # The receiver pins them here, never inside the bundle.
          - handoff: removed-predecessor
            manifest: sha256:b83a5cd1870b8ce1f2931650611f0a19deed0796c0f262e4632efc17981f695c
            head: sha256:962be71738a0146642d27c87fba3c7338b0f2bb764b113b16867bb4808b11977
          - handoff: rewired-step
            manifest: sha256:53af716cac4f889c569b687927f627a537311446521c51603077007b2581019b
            head: sha256:2177e987c877a726576703926b2ab69caa46a5f9326d1df8ac7d60056cd9c348
    steps:
      - uses: actions/checkout@v4
      # Pin the verifier to an exact core commit, like any dependency.
      # Run it from a checkout: the CLI resolves its core schemas from
      # the repository tree. This is the core commit the hosted
      # schemas are pinned to.
      - uses: actions/checkout@v4
        with:
          repository: makoto-project/makoto
          ref: 27d335292ad240fb9ebd6d5d6778a2a3ab3465f7
          path: .makoto-core
          persist-credentials: false
      - uses: astral-sh/setup-uv@v6
      - name: Verify the received bundle
        id: verify
        shell: bash
        env:
          HANDOFF: ${{ matrix.handoff }}
          EXPECTED_MANIFEST: ${{ matrix.manifest }}
          EXPECTED_HEAD: ${{ matrix.head }}
        run: |
          verify() {
            uv run --project .makoto-core makoto verify bundle "handoffs/$HANDOFF/bundle" \
              --policy receiver/policy.json \
              --schema-catalog receiver/catalog.json \
              --expected-manifest "$EXPECTED_MANIFEST" \
              --expected-head "$EXPECTED_HEAD" \
              --expected-artifact "receiver/expected/$HANDOFF.artifact.json" \
              --evaluation-time "$EVALUATION_TIME" "$@"
          }
          status=0
          verify --json > makoto-report.json || status=$?
          verify || true
          exit "$status"
      - name: Keep the verification report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: makoto-report-${{ matrix.handoff }}
          path: makoto-report.json

  rebuild-figures:
    # Runs only when every handoff in the matrix was allowed.
    needs: gate
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Rebuild figures from verified bytes
        run: echo "replace with your existing step"

    Download makoto-gate.yml. Note the second matrix entry pins the manifest and head that the rewired bundle's own handoff declares. Even when the expectations match what was sent, the lineage still has to verify.

    The gate keeps the JSON report as a build artifact, so a later job can summarize it into a signed verification summary without running verification again.

Publish the evidence beside the result

  1. Instrument export Start with exact collected bytes, acquisition time, instrument identity, and the source claim.
  2. Outlier removal Append an operation statement with predecessor bindings, code identity, parameters, and exact output.
  3. Normalization Append the next statement with the statistics and software evidence needed to interpret the claim.
  4. Publication handoff Sign the exact graph and final plotting artifact distributed with the paper.

The honest limit

Makoto can preserve the inputs and signed claims needed to reproduce the workflow. It cannot reconstruct missing intermediate bytes after publication or prove that an instrument was calibrated merely because its identifier was signed.

Concrete publication bundle

InputInstrument export, calibration reference, collection parameters, and a signed origin statement over the exact raw bytes.
StepsAppend outlier-removal, normalization, analysis, and plotting statements; bind code and parameter artifacts where available.
HandoffPublish the final figure data with the signed graph, required profiles, and exact terminal artifacts.
Reproduction checkA new researcher verifies the received bytes and can identify every missing intermediate instead of guessing it.

The checked-in customer-data proof uses the same source → two transforms → signed handoff structure with downloadable intermediate artifacts.

What else this handles

  • Journal submissions that require data availability statements with verifiable provenance.
  • Clinical datasets where every processing step must be auditable by a regulator.
  • Collaborative research where datasets pass between institutions over months.
  • Machine-learning papers where preprocessing of the training data changes the result.

Key insight. Reproducibility is not about trusting people. It is about data that can answer questions about its own history, and refusing the answer when a step is missing or rewritten.
